# ✂️ URL Shortener CLI — Консольный сервис сокращения ссылок

Приложение на Java, работающее через командную строку. Оно позволяет превращать длинные URL-адреса в короткие коды, устанавливать лимиты на количество переходов и автоматически удалять ссылки, когда истекает их срок жизни (TTL).

## 📖 О приложении

Сервис работает в режиме реального времени прямо в консоли. У каждого запуска приложения генерируется уникальный UUID пользователя (авторизация не требуется). Это нужно, чтобы система понимала, кто именно создал ссылку — редактировать и удалять записи может только их владелец.

При переходе по короткому коду система открывает браузер с оригинальным URL, считает этот переход и проверяет, не исчерпан ли установленный лимит. Если лимит кончился или прошло заданное время (по умолчанию — сутки), ссылка блокируется, а затем фоновый процесс полностью удаляет её из памяти.

## 🕹 Полная инструкция пользователя

Для запуска вам понадобится **Java 17** и **Maven**.

**1. Сборка и запуск (в терминале):**
```bash
mvn clean package
java -jar target/url-shortener-1.0.0.jar
```
**2. Доступные команды:**

После запуска введите help, чтобы вызвать подсказку. Команды вводятся в формате команда аргументы.

Сократить ссылку:

```shorten <url> [лимит_переходов]```

Пример: shorten https://www.baeldung.com/java-9-http-client 5 (создаст ссылку с лимитом в 5 переходов). Если лимит не указывать, применится значение по умолчанию (100).

Перейти по короткой ссылке:

```list```

Выводит таблицу с вашими ссылками, их кодами, текущим количеством переходов, лимитом и датой истечения срока действия.

Изменить лимит переходов:

```update <короткий_код> <новый_лимит>```

Пример: `update u1a2b3c 20`. Доступно только для ссылок, которые создали вы.

Удалить ссылку досрочно:

```delete <короткий_код>```

Удаляет ссылку из памяти (также только для владельца).

Узнать свой UUID:

```whoami```

Выйти из приложения:

```exit```

**3. Настройки (Конфигурация):**

Базовые параметры задаются в файле src/main/resources/application.properties:
```
link.ttl.hours=24              # Время жизни ссылки в часах
link.max.visits.default=100    # Лимит переходов по умолчанию
cleanup.interval.seconds=60    # Как часто фоновый поток удаляет просроченные ссылки
```

## 🧪 Тестирование

В проекте настроены Unit-тесты и интеграционные сценарии (JUnit 5). Они проверяют генерацию уникальных кодов для разных пользователей, блокировку при превышении лимита, права доступа и работу планировщика по удалению «протухших» ссылок.

Для запуска тестов:

```mvn test```

Также настроен GitHub Actions (.github/workflows/ci.yml), который прогоняет тесты при каждом пуше.

## 🏗 Как создавалось приложение (Архитектура и логика)

При разработке проекта я в первую очередь опиралась на требования заказчика и техническое задание. Моей целью было не просто написать рабочий код, а спроектировать грамотную и масштабируемую архитектуру, которая легко выдержит добавление новых функций в будущем. Поэтому в основу легли принципы SOLID и Clean Architecture, позволившие четко разделить зоны ответственности и сделать систему надежной.

**1. Слои и разделение ответственности (база для масштабируемости):**
*   **Слой `core`** — это сердце приложения. Я поместила туда всю бизнес-логику (`LinkServiceImpl`) и модели данных (`ShortLink`, `UserContext`). Благодаря этому сервис ничего не знает о том, как и где хранятся данные или как с ним общается пользователь. Он просто принимает данные, проверяет условия и возвращает результат, что позволяет легко тестировать логику в изоляции.
*   **Слой `infra`** — отвечает за инфраструктуру. Я специально использовала интерфейс `LinkRepository`, чтобы обеспечить ту самую масштабируемость: в будущем можно будет легко заменить текущее `InMemoryLinkRepository` (на базе потокобезопасного `ConcurrentHashMap`) на реальную базу данных (PostgreSQL или Redis), не меняя ни строчки в `core`. Здесь же работает `CleanupScheduler` — фоновый поток, который раз в минуту сканирует память и удаляет ссылки с истекшим TTL.
*   **Слой `ui`** — класс `ConsoleUI`. Он полностью изолирован от бизнес-логики. Его задача — прочитать строку, разобрать её на команды и вызвать нужный метод сервиса, а затем красиво вывести ответ. Также здесь я реализовала автоматический редирект в браузер через `Desktop.getDesktop().browse()`.

**2. Логика уникальности и безопасности:**
*   Чтобы решить проблему одинаковых ссылок (когда два разных пользователя сокращают один и тот же URL), я заложила в алгоритм генерации короткого кода хэширование комбинации: `UUID пользователя + сама ссылка + случайное число (nanoTime)`. Это гарантирует уникальность кодов для каждого пользователя и исключает коллизии.
*   Безопасность реализована через проверку прав доступа: каждый объект `ShortLink` хранит в себе `UUID` создателя. Перед редактированием или удалением сервис сверяет UUID текущего пользователя с UUID владельца и выбрасывает исключение, если они не совпадают, защищая данные от посторонних.

**3. Работа со временем и состоянием:**
Каждая ссылка хранит `LocalDateTime expiresAt`. При любом обращении к ссылке (команда `open`) система сначала проверяет: не истек ли срок и не превышен ли лимит. Если да — ссылка блокируется, и пользователю выводится понятное уведомление с предложением создать новую. Это позволяет автоматизировать жизненный цикл ссылки без участия человека.
